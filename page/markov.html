Markov Chains and Dynamic Programming

May 09, 2026

Markov chains are a powerful mathematical tool for modelling a variety of random processes, and answering questions about them. Here, we look at what they are, and use them to solve some problems.

Markov Chains

A Markov chain is a random process which follows the Markovian property: At any point in time, the probability of the next event only depends on the current state.

For example, consider a random walk on the integers line, starting at 0. At each step, there is a 50% chance that the agent moves right by one step, or left by one step. Here, the ‘state’ of the system is where the agent currently is situated. The next move of the agent is probabilistic, but it only depends on the current state, not the past history of states. Thus, this process can be modelled as a Markov chain.

More formally, a (discrete-time) Markov chain is a sequence of random variables 𝑋𝑖, where 𝑃(𝑋𝑛+1=𝑥|𝑋1,𝑋2,…,𝑋𝑛)=𝑃(𝑋𝑛+1=𝑥|𝑋𝑛) (distribution of 𝑋𝑛+1 only depends on 𝑋𝑛).

Here, the states denote the number of consecutive heads seen yet, which can be 0, 1 or 2. At each step, we flip a coin, and we get one more consecutive heads, or we get a tails, which resets our head count. Since the state transition only depends on the previous state, this process is Markovian.

Here, the state 2 is called an ‘absorbing state’, as once we reach this state, we don’t do any more coin tosses and remain on this state indefinitely (represented as a single transition 2→2 with probability 1). Formalism

We can formalise the technique we used above to calculate the expected hitting time in a Markov chain.

Consider a Markov chain. Let 𝑝𝑖𝑗 denote the transition probability from state 𝑖 to state 𝑗. Let 𝐴 be a subset of states which are the absorbing states. Represent by 𝑘𝑖𝐴 the expected hitting time for 𝐴, if starting at state 𝑖. For any other state 𝑖∉𝐴, let 𝐻𝐴 denote the hitting time. So, 𝑘𝑖𝐴=𝔼(𝐻𝐴|𝑋0=𝑖).

Dynamic Programming

Let’s look at an example where we can use Markov chains to formulate the expected hitting time equations, and use dynamic programming to compute the answer.

Consider the following problem: (Adapted from: Atcoder Educational DP Contest)

There are 𝑁 dishes, numbered from 1 to 𝑁. Initially for each 𝑖, dish 𝑖 has 𝑎𝑖 (1≤𝑎𝑖≤3) pieces of sushi on it. You perform the following operation repeatedly until all the pieces of sushi are eaten:

  • Randomly choose a dish 𝑖, 1≤𝑖≤𝑁. If dish 𝑖 is not empty, eat a piece of sushi from that dish.

What is the expected number of operations performed?

Once again, this problem can be modelled by a Markov chain.

An initial choice of the state of the system can be the counts of pieces of sushi on each dish at some time. So, the initial state will be (𝑎1,𝑎2,…,𝑎𝑁), and the final (absorbing) state is (0,0,…,0). Transitions will be with probability 1𝑁, decrease by one the value of the 𝑖th dish (if it is non-zero, or stay on the same state otherwise).

This is a perfectly fine choice of state definition, but the total number of states here is ∼3𝑁, which is impractical to represent in a dynamic programming solution.

Here, we can actually compress our state space, by only keeping relevant information for our needs. We define our states and transitions as follows:

  • A state (𝑖,𝑗,𝑘) represents that there are 𝑖 dishes with one piece of sushi, 𝑗 dishes with two pieces of sushi, 𝑘 dishes with three pieces of sushi, and the rest of the dishes have no pieces of sushi.
  • Initial state is (#1(𝑎),#2(𝑎),#3(𝑎)) and the final absorbing state is (0,0,0) (all dishes are empty).
  • With probability 𝑖/𝑁, we transition to the state (𝑖−1,𝑗,𝑘) (choose a dish with one piece of sushi), with probability 𝑗/𝑁, we transition to the state (𝑖+1,𝑗−1,𝑘) (choose a dish with two pieces of sushi), with probability 𝑘/𝑁, we transition to the state (𝑖,𝑗+1,𝑘−1) (choose a dish with three pieces of sushi), and with probability 1−𝑖+𝑗+𝑘𝑁 we stay on the same state (choose an empty dish).

We can clearly see the advantage here, we only require ∼𝑁3 states under this definition.

Now, using our above theorem, we can write down the relations between the hitting times. We need to find the hitting time to the state (0,0,0), starting from our initial state. Let 𝑇(𝑖,𝑗,𝑘) denote the hitting time from state (𝑖,𝑗,𝑘). Then,

𝑇(𝑖,𝑗,𝑘)=1+(1−𝑖+𝑗+𝑘𝑁)𝑇(𝑖,𝑗,𝑘)+𝑖𝑁𝑇(𝑖−1,𝑗,𝑘)+𝑗𝑁𝑇(𝑖+1,𝑗−1,𝑘)+𝑘𝑁𝑇(𝑖,𝑗+1,𝑘−1)⇒𝑇(𝑖,𝑗,𝑘)=𝑁𝑠+𝑖𝑠𝑇(𝑖−1,𝑗,𝑘)+𝑗𝑠𝑇(𝑖+1,𝑗−1,𝑘)+𝑘𝑠𝑇(𝑖,𝑗+1,𝑘−1)

We have, 𝑇(0,0,0)=0, and we need to find 𝑇(#1(𝑎),#2(𝑎),#3(𝑎)).

Note that the recurrence relation of 𝑇(𝑖,𝑗,𝑘) depends on both states with 𝑖−1 and 𝑖+1, so finding an appropriate ordering for doing a bottom-up computation is not trivial. So, we can get a memoized recursive top-down solution.

Though, we can say that the recursion must terminate, as the transitions always decrease the weighted value 𝑖+2𝑗+3𝑘. (This can be used to get a topological ordering to get a bottom-up solution!)

Here’s the recursive implementation of the above DP:

double solve(int i, int j, int k, int n, vector<vector<vector<double>>> &dp) {
    if (i == 0 && j == 0 && k == 0) return 0;
    if (dp[i][j][k] > 0) return dp[i][j][k];
    
    double ans = 0, s = i + j + k;
    if (i) ans += solve(i - 1, j,     k,     n, dp) * i / s;
    if (j) ans += solve(i + 1, j - 1, k,     n, dp) * j / s;
    if (k) ans += solve(i,     j + 1, k - 1, n, dp) * k / s;
    
    return dp[i][j][k] = ans + (double)n / s;
}

As we saw through these examples, Markov chains allow us to cleanly express the behaviour of a random process in a mathematical way. Most probabilistic processes can be modelled as Markov chains, and we can use the properties of Markov chains to answer questions about these processes.
